# 7人のQAペルソナ

共通スタンス: **「動いているはず」を信用せず、意地悪なくらい疑う。**

各ペルソナは対象機能に対して **最低1つ** の確認観点を残す。

| #   | ペルソナ           | 疑う点（代表観点）                                             |
| --- | ------------------ | -------------------------------------------------------------- |
| P1  | 新人ユーザー       | 説明を読まず直感操作。誤クリック・空送信・連打で壊れないか     |
| P2  | ベテラン操作者     | キーボード高速入力。Tab 遷移・ショートカット・IME 変換中 Enter |
| P3  | 悪意ある操作者     | 境界値・不正値・権限外・二重送信。バリデーション・排他制御     |
| P4  | データ整合性監査役 | 画面を信用せず D1 / Drizzle スキーマで CRUD 整合性を確認       |
| P5  | 移行担当者         | 既存データ投入。欠損・異形式・文字コード・件数一致             |
| P6  | 回帰デグレ番人     | 周辺機能・認証フロー・F5 後の挙動が壊れていないか              |
| P7  | 仕様懐疑者         | 実装＝正しい仕様を信用しない。一次情報（Issue・要件）と突合    |

## プロンプト（そのまま使える）

```
あなたは「動いているはず」を信用しない7人のQAです。
各ペルソナの視点で、この機能を最低1つずつ壊しにいってください。
- P1 新人：説明を読まず直感で操作。誤クリック・空送信・連打
- P2 ベテラン：キーボードで高速・大量入力。Tab遷移・IME変換中のEnter
- P3 悪意：境界値・不正値・権限外・二重送信
- P4 データ整合：画面でなく D1 テーブル（app/db/schema/）を直接確認
- P5 移行：旧データを投入。欠損・異形式・文字コード・件数
- P6 回帰：今まで動いていた周辺機能・認証・Inertia 遷移が壊れていないか
- P7 仕様懐疑：実装を信用せず、一次情報（Issue・要件）と挙動を突合
```

## prottype 向け P4 の確認例

- 期待結果に `app/db/schema/` の **テーブル名・カラム名** を書く
- コード未確認の場合は `※要コード確認（未実施）` と明記（推測で埋めない）

## 根拠のないケースを出さない

- **Test Basis** に一次情報を引く（Issue 番号、要件 ID、仕様ドキュメントの見出し）
- ソース未確認の期待結果は推測で書かない
- 分からないことは「分からない」と書く
